## 结论

建议第一阶段从 **通知公告 → 学生通知** 开始：

- 入口：<https://uc.whu.edu.cn/tzgg/xstz.htm>
- 对应栏目 ID：`1517`（列表文章新式 URL 使用 `/info/1517/<id>.htm`；旧式 URL 使用 `wbtreeid=1517`）。

## 观察事实：请求、页面与提取字段

### 普通 HTTP 可用性

用不带站点 Cookie 的普通 GET 实际抓取了列表第 1、2 页及新旧两种详情页；全部返回 200。请求使用带研究名称的 User-Agent，没有浏览器脚本或登录流程。响应头表明站点使用 `WHU-AppSrv 1.0.0`。

| 页面 | 请求 URL | 实测响应 |
|---|---|---|
| 学生通知第 1 页 | `https://uc.whu.edu.cn/tzgg/xstz.htm` | `200 text/html`，22,277 bytes；`Cache-Control: private, max-age=600`；有 `ETag`、`Last-Modified` |
| 学生通知第 2 页 | `https://uc.whu.edu.cn/tzgg/xstz/23.htm` | `200 text/html`，23,134 bytes；有相同类型缓存头及验证器 |
| 新式详情 | `https://uc.whu.edu.cn/info/1517/128231.htm` | `200 text/html`，49,563 bytes；有 `ETag`、`Last-Modified`、10 分钟缓存头 |
| 旧式详情 | `https://uc.whu.edu.cn/2022/show.jsp?urltype=news.NewsContentUrl&wbtreeid=1517&wbnewsid=127581` | `200 text/html;charset=UTF-8`，31,922 bytes，chunked；该样本响应未见 `ETag` / `Last-Modified` |

对第 1 页带原始 `If-None-Match: "5705-65c324a9c2548-gzip"` 再发一次 GET，服务器返回 **304 Not Modified，0 bytes**。因此列表可用条件 GET 做低流量轮询。详情页样本也带有验证器，但没有单独验证其条件 GET 行为。

沙箱内初次请求因 DNS 解析失败；网页抓取端对首页返回 403。之后以有限次数的直接 HTTP GET 成功取得列表和详情原文。这个 403 是网页抓取端的限制，不是站点要求使用浏览器的证据。现有浏览器仅用于观察附件端点的验证码页面；无需用浏览器采集列表或正文。

### 列表字段与分页

**HTML 观察：** 列表主体是 `div.list_txt > ul.am-list > li > a`。每个文章链接下有 `span` 标题和 `i` 日期；链接可能是相对地址，必须相对于当前列表 URL 做 URL 解析。原始 HTML 标题不含页面无障碍树显示的 `◆` 装饰符，因此不要把该符号写进标题。

可直接提取：

- `title`：`a > span` 的文本
- `published_date`：`a > i` 的 `YYYY-MM-DD`
- `detail_url`：`a[href]` 解析后的绝对 URL
- `source_category`：固定为学生通知 / `1517`

每页实测 25 条。第 1 页分页显示 1–24 页：第 2 页链接为 `xstz/23.htm`，第 3 页为 `xstz/22.htm`，第 24 页（尾页）为 `xstz/1.htm`。第 2 页的“下页”链接指向 `22.htm`。也就是说静态路由文件名与可见页码反向递减；应沿 HTML 的“下页”链接遍历，不应自行拼接页码。只实际抓取并核对了前两页，末页未请求；总记录数未知。若其余页也都是 25 条，当前档案约为 576–600 条，这是估算而非实测。

第 1 页一个可复核样例：`2026-09-04` 的“武汉大学2027届推荐优秀应届本科毕业生免试攻读研究生拟推荐名单公示”（ID `128281`）排在 `2026-09-09` 的文章之前。该行与其他行使用相同 HTML 结构，没有“置顶”文本或独有 class。

### 详情和两种 URL 形态

两种路径都可直接 GET，样本页面有相同的 `div.title_nei` 标题区和 `#vsb_content .v_news_content` 正文区。

| 路径形态 | 示例 | 文章 ID 提取 |
|---|---|---|
| 新式 | `/info/1517/128231.htm` | 路径中的 `1517` 和 `128231` |
| 旧式 | `/2022/show.jsp?urltype=news.NewsContentUrl&wbtreeid=1517&wbnewsid=127581` | 查询参数 `wbtreeid=1517`、`wbnewsid=127581` |

**建议字段提取：** 标题取 `.title_nei b`，发布时间取 `.title_nei i`；正文保留 `#vsb_content .v_news_content` 的段落、表格、链接和图片引用，不要只取扁平文本。正文可能含重要图表：旧式选课通知样本内有一张说明选课时段的图片，纯文本抽取会漏掉图中时间表。

附件列表出现在 `div.fj ul li a`。锚文本是文件名，`href` 是下载端点。样本中新式详情有 2 个 PDF 附件，旧式详情有 1 个 PDF 和 2 个 DOCX。下载次数由 `getClickTimes(...)` 等脚本填充，列表点击统计也使用 `_showDynClickBatch(...)`；这些动态计数不是通知正文，不应依赖它们完成采集。

### 附件限制

验证过的附件链接形态为：

`https://uc.whu.edu.cn/system/_content/download.jsp?urltype=news.DownloadAttachUrl&owner=1407739091&wbfileid=<文件ID>`

对旧式详情中的一个 PDF 下载链接直接导航后，服务器显示“请输入验证码下载附件”表单（含 `codeValue`、验证码图及“确定”按钮），没有直接交付二进制文件。没有尝试识别或绕过验证码。样本详情页的附件名称和 URL 本身可从 HTML 免费取得；**附件端点是否对所有文件都要求验证码尚未逐一验证**，但不能把链接存在当成文件可自动下载。

### 访问规则与限制

- `/robots.txt` 导航得到站点自定义 404 页面；这不能证明没有其他公开抓取规则，只能说该路径没有提供可读规则文件。
- 列表页和新式详情的 `Cache-Control` 为 `private, max-age=600`，并带 ETag/Last-Modified。尊重 10 分钟缓存；单次条件 GET 已确认能返回 304。
- 本次没有遇到列表/正文验证码、登录要求或速率限制，也没有做并发、压力或大规模全档案测试。因此站点限速阈值、封禁策略和允许的长期轮询频率均未知。

## 事实、推测与设计建议

### 置顶与顺序

- **事实：** 第 1 页存在日期倒序的 `2026-09-04` 文章，位置在 `2026-09-09` 文章之前；原始行没有显式置顶标识。
- **推测：** 该文章可能被置顶或由编辑手工排在前面。单次快照无法区分这两种原因，也无法确认置顶项是否跨页重复出现。
- **建议：** 不用日期或“遇到旧条目就停止”作为结束条件。遍历列表时先收齐每页所有行，并按文章 ID 去重；发现日期倒序时保留记录。

### 更新与缓存

- **事实：** 列表页 ETag 条件 GET 返回 304。新式详情的可见发布时间为 2026-09-04，而响应 `Last-Modified` 为 2026-09-10；两者不是同一个字段。旧式详情样本未返回 ETag/Last-Modified。
- **未知：** Last-Modified 是否对应正文真正编辑时间、站点会否原 URL 覆盖正文、删除或撤回通知后列表如何表现、旧式路由是否始终没有验证器。
- **建议：** 将站点显示日期和 HTTP 验证器分别保存。记录正文规范化后的 hash；对近期已知详情定期条件重取，若旧式路由没有验证器则低频 GET 后比 hash。不要把 Last-Modified 当成公告发布时间。

### 重复链接与身份

- **事实：** 同一栏目列表混用 `/info/1517/<id>.htm` 和 `show.jsp?...wbtreeid=1517&wbnewsid=<id>` 两种文章链接。前两页样本的 ID 连续区间未见明显重叠；没有观察到同一文章同时以两种路径出现。
- **未知：** 站点是否会将同一公告重复发布为不同文章 ID，或让一篇文章同时出现在不同栏目/分页。
- **建议：** 在栏目范围内用 `(wbtreeid, article_id)` 作为规范身份：新式路径中的栏目/ID 与旧式查询参数统一到此键；保留原始 URL 供审计。不要仅按标题去重，年度通知可能标题相似但确实是不同公告。附件按 `(owner, wbfileid)` 去重。

### 停机后的补抓

- **建议：** 正常运行时每 30 分钟用首页 ETag 条件 GET 一次；304 不解析、不取详情。首页变化后沿“下页”逐页取到与本地已知 ID 完全重叠的一整页，再多保留一页重叠缓冲；只为新 ID 取详情。30 分钟是起步配置，不是站点公布的要求，远高于实测 10 分钟缓存期限。
- **建议：** 长停机恢复时，不信任之前的页码游标（插入新文会移动页边界），从第 1 页开始按当前分页链完整走到尾页，按文章 ID 幂等入库。当前约 24 页，每页 25 条，列表全量回扫的请求数有明确上限；若站点继续增长，仍以“下页”是否存在作为终止条件。
- **建议：** 每日或在页面 ETag 改变时复核近期详情，发现正文 hash 变化时更新既有通知。仅靠列表无法发现早期文章内容被修改或撤回。
- **未知：** 本站分页边界是否稳定、列表缓存的发布延迟、停机期间被删除的文章能否从公开网页恢复，以及置顶文章会否造成跨页重复。

## 最小采集方案

1. 每次对 `https://uc.whu.edu.cn/tzgg/xstz.htm` 发普通 GET，带上已存 ETag；接受 304。不要短于服务器声明的 10 分钟缓存窗口轮询。
2. 对 200 响应，仅解析 `ul.am-list` 下的 25 行，按页面 `下页` 链接遍历到已知重叠区或尾页；保存原始相对链接、解析后的绝对链接、标题、站点日期、栏目 ID 和抓取时间。
3. 对新文章按两种路由解析 canonical ID，再 GET 详情；保存原始 HTML、HTTP 验证器、抽取字段、正文 hash、正文内链接/图片引用、附件文件名及下载 URL。
4. 自动化采集先停在附件元数据，不提交验证码。对正文图片保留 URL；若通知关键信息只在图片中，标注待人工查看。对附件需另行设计经授权的人工下载流程。
5. 超时和 5xx 可少量退避重试；403、验证码、空白响应或解析字段缺失要记录失败并告警，不能当作“本轮没有新通知”，也不要反复重试验证码。避免并发扫站；具体限速仍需长期观察。

## 可能漏报的路径

- 附件端点验证码阻断自动取文件；附件独有的截止日期、名单或表格将漏报。
- 通知正文的内嵌图片（已在样本中观察到）可能包含唯一时间表；纯文本会漏。
- 学生通知以外的“综合业务”、学院/部门网站、研究生院、学工部、教务系统登录后通知不在覆盖范围。
- 若新通知在两次轮询间发布后迅速被推到第 1 页 25 条以外，单看首页会漏；变化时需按分页追到已知重叠边界。
- 早期详情修订/撤回不会必然触发首页变化；不复核旧详情就可能保留过期内容。
- 临时网络错误、源站 403、页面模板改版或附件验证码若被误判为空列表，会造成静默漏报；解析结果应有行数/必需字段校验和错误状态。
