## 证据和标注

语料为 **9 篇真实 HTML**：本科生院 8 篇、EMS 历史助教选聘 1 篇。
包括科研训练课程、大创征题及立项、项目结题、辅修报名、普通及新生选课、真实比赛。
文件直接复用 research 中已有原文，未重新下载或改写。EMS 仅是人工登记目标的离线语料，
不表示已接入 EMS 自动发现，更不表示已取得需要登录的当期招聘正文。

**15 个查询**依据用户提出的真实使用类别具体化，包含“助教招聘”“科研训练”
“最近一个月的竞赛”、多词、来源和日期过滤；不是用户搜索日志。
13 个查询有相关目标，2 个预期为空；科研训练有 3 个相关目标，选课有 4 个，
创新创业训练计划有 2 个，不把所有例子都简化为唯一命中。
相关性、负例及理由均为**尚未经用户逐条确认的工程判断**，报告始终 `human_gold=false`。
它们是可审查的回归依据，不能声称为人工确认的检索质量基准。

“最近一个月”没有交给代码猜测。S05/S06 明确以 2024-07-01 为锚点，
使用 2024-06-01 至 2024-07-01 的站点发布日期过滤。其他查询同样显式填写过滤项。
原文获取于 2026 年不改变 2024 年的发布日期；获取时间和处理时间不会替代站点日期。

## 方法比较与选择

每次运行新建临时 SQLite 实例，通过真实 RawStore、`import_page`、对应 Parser、
业务成功版本及 `rebuild_index` 建立语料；直接登记已知离线详情目标，
不伪造列表、完整扫描或生产通知启用。基线在独立内存 SQLite 中对同一批成功正文计算：

1. 参数化 `instr` 字面 AND，标题命中优先，然后站点日期与稳定 ID。
2. FTS5 默认 unicode61，字面片段 AND，BM25 标题权重 5、正文权重 1。
3. FTS5 trigram，三字以上片段用索引，短片段用 `instr`，全部条件最终字面复核。
4. 上述 trigram 加有限、固定、显式的查询别名；组内 OR，空格分组之间 AND。
5. 最终生产 `search_notices`，不是研究脚本中的简化检索器。

SQLite 的 [FTS5 官方文档](https://www.sqlite.org/fts5.html#the_trigram_tokenizer)
说明 trigram 的子串检索及少于三个字符的限制。
本次实测默认 unicode61 在这些中文正文上召回不足；没有据此宣称它对所有中文场景无用。
选择 trigram 保持片段检索语义，并保留两字“助教”“竞赛”的参数化回退。
小语料没有证明索引速度优势，**未做延迟、规模或磁盘基准测试**。

原词“助教招聘”在历史正例中不存在，正文和标题使用“助教选聘”；
真实竞赛标题用“大赛”。仅字面匹配会漏掉两个核心查询。因此生产采用
`query_version=literal-alias-v1`，固定别名如下：

| 精确查询片段 | 允许匹配的字面短语 |
| --- | --- |
| 助教招聘 | 助教招聘、助教选聘、招聘助教、选聘助教、助教招募 |
| 竞赛 | 竞赛、大赛 |

它们有真实措辞依据；没有中文分词模型、网络词典或任意语义改写。
裸词“助教”不会自动变成招聘，“科研训练”不会自动变成“大创”。
结果同时保留原始 query、实际 `expanded_terms` 和规则版本，可以看到用了哪些词。
索引版本为 `literal-trigram-v1`，与查询别名版本独立；这不修改通知政策、内容摘要或旧邮件。

## 实际结果

以下是 **13 个非空相关集的宏平均 Recall@K**；2 个空集另报，未拿它们抬高 Recall。

| 方法 | Recall@1 | Recall@3 | Recall@5 |
| --- | ---: | ---: | ---: |
| SQLite 字面 AND | 0.621795 | 0.750000 | 0.769231 |
| FTS5 unicode61 | 0.019231 | 0.038462 | 0.038462 |
| FTS5 trigram，无别名 | 0.621795 | 0.750000 | 0.769231 |
| FTS5 trigram，固定别名 | 0.852564 | 0.980769 | 1.000000 |
| **生产索引及搜索接口** | **0.852564** | **0.980769** | **1.000000** |

生产输出与固定别名候选的逐查询结果一致。2 个来源/日期空查询均正确返回空；
重建后逐条结果、排序、引用及版本一致。脚本固定输入和相关源码的 SHA-256，
运行中源码变化会明确失败；当前快照不能拿来代表后来已变更的代码。

别名有代价：S15 不限定日期查询“竞赛”时，真实比赛排第一，另返回两篇顺带提到竞赛的
科研/课程通知，**该例前 3 条精确率为 1/3**。全体非空查询前 5 条已返回结果内的宏平均
精确率为 0.948718；标准固定分母 Precision@5 为 0.292308，因为多数查询的全部相关
目标本来不足 5 条。报告分开记录两种精确率，不能互相替换或只宣称“100%准确”。

“助教招聘”只返回 EMS 选聘正例，没有把配备现有助教的课程误当招聘。
这仍然是历史检索相关性，不意味着招聘当前开放、用户符合资格或应该发送邮件。
其他未配置的近义词、隔断措辞和自然语言相对日期仍可能漏检；正文中的顺带提及仍可能误检。
图片、附件文件内容和未成功解析的通知不在此次索引内。

在已安装锁定依赖的仓库运行，默认不联网，不读个人配置或生产数据库，不发送邮件：

```sh
uv run --locked python deploy/evaluate_search.py --check
# 新快照使用新文件名，命令拒绝覆盖已有结果。
uv run --locked python deploy/evaluate_search.py --check --output /tmp/search-replay.json
uv run --locked pytest tests/test_search_evaluation.py
uv run --locked ruff check deploy/evaluate_search.py tests/test_search_evaluation.py
uv run --locked ruff format --check deploy/evaluate_search.py tests/test_search_evaluation.py
```

`--check` 只验证已声明的工程目标是否在前 5 条，以及预期空查询是否为空；
不会把已知误检藏起来，也不代表通过了用户相关性验收。18 项评估测试通过，
覆盖真实生产回放、确定性及快照绑定、别名收益和误检、日期/来源、路径/摘要、
标签与目标校验、运行中源码变化、命令错误退出及帮助无副作用。
项目全部测试和部署端验证由本轮交付汇总另行记录。

后续应由用户确认这些标签，增加真实搜索记录、更多比赛/招聘及同主题干扰页，
再决定是否扩展词典、分词或排序。不要用这 9 篇语料的 Recall@5=1.0 外推全站质量。
