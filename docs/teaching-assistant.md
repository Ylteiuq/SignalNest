# 新迭代 N1：助教招聘的离线能力

本编号属于 2026-10-08 新迭代，和原邮件模块 N1 持久化阶段分开。已实现正式主题、有限招聘行动/申请对象/时间判断、一个独立的经管学院详情 Parser、本地 CLI 预览，以及连接真实归档和 SQLite 的离线测试。没有接入新网络来源、发送邮件或部署实例。

**可以验收真实历史招聘的离线判断；自动发现当期助教机会仍未验收。** 经管学院栏目不属于现有本科生院来源。已有研究取得的当期详情响应跳转到统一登录，没有公开正文；不能用 2024 条件推断 2026 对象、截止或可申请性，也不绕过登录。

2026-10-10 后续节点已完成[计算机学院本科教学真实样本的离线适配](cs-undergrad.md)：列表/正文、显式 CS 预览、假设本科画像的资格/年份待核对、归档/重解析和政策 v7。本文下方 v5 版本与2026-10-08验证数字为历史记录；current 评估按 v7 重放，EMS v1 与其原始六情境保持。计算机学院自动采集仍是下一节点，现有生产来源不变。

## 样本与规则

原样使用[来源研究](../research/teaching-assistant-source-20261008.md)中的官方历史正例：经济与管理学院《2024—2025 学年第一学期本科教学课程助教选聘通知》，稳定身份 `1588:250571`，站点日期 2024-09-09。完整原文实际于 2026-10-08 获取，附件只有名称/URL/owner/wbfileid，保持 not_checked。正文 9/27 公布审核结果、10/31 和 12/30 提交考核表，均不是初次岗位申请截止。

真实负例为本科生院 128291 的现有助教/科研课程介绍，以及武汉大学新闻网《我怎样当助教》的任职经验、历史选聘统计。后者只作为真实文本负例，没有为新闻网增加生产 Parser 或采集来源。所有画像、历史时钟和预期 Action 都是工程回归输入，没有新增人工 gold。

Profile 正式支持 `teaching_assistant`，可用于兴趣、高价值、排除和仅保存主题；严格拒绝拼写错误。`profile.teaching-assistant.example.toml` 是虚构硕士申请者示例。原示例画像保持不变，不替用户增加兴趣或假设个人身份。

招聘需要“助教/教学助理”与招聘、招募、选聘等有限关系，并有可关联的当前招聘或申请证据。明确招聘标题可关联正文的当前报名/登录完成报名指令，或样本中的申请审核表提交指令；另一个具名主题的报名不能借给助教，另一句泛指报名也不能越过竞争机会。没有可识别当前行动的招聘标题保留 uncertain 和 topic_action_link_unknown；菜单、缴费、津贴、退出、考核、历史记录和明确未开放的招聘不作为当前机会。正文裸“助教”始终只是 incidental，不会因为标题或正文出现该词就进入 Digest。显式 include_phrases 仍是用户选择的宽泛字面关注。

“本科教学课程”说明受益课程，不推导本科生申请资格；“学院各系（所）”是收件单位，不推导教师申请者。真实“原则上从本院全日制研究生中选聘”保留对象、院属、学籍和软限定证据：原则上不成为硬排除，不能确认本科生一定不符合，也不能宣称硕士一定符合。主讲教师签署聘用意见、附件内条件继续待核对。严格且无软限定的明确申请对象仍可对已知不匹配 Profile 作资格排除。

时间只补样本支持的初次岗位申请表提交句：完整年月日、可选且与日期一致的周几、下午 13–23 点前，按 Asia/Shanghai 解释。样本为 **2024-09-20 16:00**；不会截断“下午4点”“16点30分”“16时”后猜时刻，日期或星期矛盾也保留未知。此有限表达式仅用于申请表，不全局接收任意中文时刻，不从发布日期补年份。明确当前申请指令可以确认开放而不虚构 opens_at。后续公布、考核和续聘流程日期不抢占初次申请截止。

历史回放 2024-09-20 09:00 时，普通助教兴趣、没有已知硬资格冲突即可得到 PUSH_NOW/deadline_soon/immediate，同时 eligibility unknown、needs_review。提醒表示及时核对，不代表资格通过。以真实 2026 获取后时间作 new 判断时，该岗位已关闭，沿用既有 IGNORE/none 语义，业务正文仍保留；不改 STORE_ONLY/IGNORE 的边界。

## 本地预览

在仓库根目录安装现有依赖后：

```sh
uv run --locked signalnest profile-check --profile profile.teaching-assistant.example.toml
# 显式历史回放；不是当前开放岗位，也不修改获取时间。
uv run --locked signalnest decision-preview \
  --profile profile.teaching-assistant.example.toml --parser ems-notices \
  --file research/fixtures/teaching-assistant/ems-notice-250571-20261008T102823953399Z.html \
  --url https://ems.whu.edu.cn/info/1588/250571.htm \
  --at 2024-09-20T09:00:00+08:00 --next-digest-at 2024-09-21T09:00:00+08:00
# 将以上时钟改为 2026-10-08 和次日，可检查已截止的判断。
```

`decision-preview --parser` 仅针对 --file HTML，默认 whu-student-notices 保持兼容；ems-notices 必须显式选择。--notice-json 已是规范内容，不接受非默认 Parser 选择。不根据文件名猜站点，不在 Parser 失败后自动换模板。帮助和预览不读取业务库、不获取写入锁、不联网、不计划邮件。

## 模块与来源边界

`signalnest.ems_parsing.parse_ems_notice(PageInput) -> ParsedNotice` 仅支持已观察的 EMS 栏目 1588 详情路由：`/info/1588/<id>.htm` 和 `/2025/content.jsp?...wbtreeid=1588&wbnewsid=<id>`，统一为 `1588:<id>`。正文要求 article 中的明确表单、标题、可见发布日期和内容节点；登录、错误页、重复或缺失结构明确 ParseError。版本为 ems-notices-v1，独立于原本科生院 whu-student-notices-v3；后者分页、身份、附件和内容摘要规则不变。

新模块复用现有严格 UTF-8、正文清洗、HTTP(S) 引用和摘要契约；图片/外链输出绝对引用，下载统计与前后篇导航不进正文。仅保留引用，不执行 JS 或下载媒体。HTML 保留不等于安全清洗，后续界面不能直接信任并渲染。

现有 `import_page(..., notice_parser=parse_ems_notice, processing_origin="offline")` 和 `process_response(..., notice_parser=parse_ems_notice, processing_origin="maintenance")` 可由库调用者复用。先显式人工登记独立来源下的目标通知、持 writer_lock，再导入已知获取元数据；没有 EMS 列表适配，不能伪称完成扫描。CLI import-page/reparse 仍使用原来源 Parser，不增加不完整的第二来源导入模式。生产 Fetcher 白名单和协调器均不变，EMS 请求明确拒绝。

离线入库不会创建 live 事件、投递意图或冻结邮件。端到端测试分别验证：真实 2026 元数据 → 原始归档/响应 → EMS Parser → 幂等版本/重开库；以及相同正文 → 显式 2024 回放 → 决策 → 现有纯 render_mail 生成确定 MIME 预览字节。预览 ID 是纯函数输入，不是库中真实事件；不能称为生产邮件计划、冻结任务、SMTP 验收或当期招聘覆盖。

## 版本与评估

事实/规则/决策版本升为 whu-notice-facts-v5、notification-rules-v5、notification-decision-v5，路线仍 v1。固定招聘/时间规则纳入 policy_manifest，未添加运行时可变配置、数据库迁移或依赖。已有实例须按[显式政策升级](notifications.md#已有实例显式升级政策)发布新 operation ID；不静默重写旧决策、已有投递资格或冻结邮件。维护重解析不制造内容更新邮件。

[六个固定用例](validation/teaching-assistant-cases.json)和[实际结果](validation/teaching-assistant-current.json)单列；不改变原 13 个本科生院工程回归或两个 N0 最小输入。6 例的工程预期为 PUSH_NOW 3、DIGEST 1、IGNORE 2，涵盖当前已关闭、历史临近截止、软资格不硬排、现有助教负例和科研跨主题优先级，均保留需要的未知条件。历史 v4 全量 seal 和评估快照在升级前保存；工程通过率不能替代人工准确率、当前岗位验证或全站召回率。

## 后续来源适配任务

1. 确认当期招聘可公开访问的官方正文、栏目和权限边界；仅凭列表标题不能使用历史资格/截止发提醒。
2. 单独取得可复核的 EMS 首页、中间页、真实末页与元数据，验证 mixed-category/外链/置顶/路由和分页终止证据。
3. 明确当前单来源实例/通知通道如何接入第二来源，再实现有限目标校验、列表 Parser 与协调器选择；不只放宽主机白名单。
4. 用模拟 HTTP 接真实归档/缓存/Parser/DB/事件/邮件计划验证完整覆盖、304、失败补抓、政策启用和独立 live 基线，再做少量低频真实公开页验证。
5. 当期正例可用后重新核验个人资格和附件条件，才验收自动发现助教机会。该缺口不阻止 N2 先部署既有本科生院来源。
