## 真实 SMTP 与隔离工程邮件

生产库没有合成记录。独立目录 `/var/lib/signalnest-validation/signalnest-mail-acceptance`
使用真实迁移、RawStore、Parser、通知成功事务、决策、冻结、发送协调器及 SMTP 适配器。
其页面、200 元数据和覆盖声明**均为明确标记的工程模拟输入**，不是实际网站响应或真实完整扫描。
模拟获取时间只表示本地生成时刻；不能将该库用于生产或证明校园提醒质量。

测试成员标题与正文明确写明“工程验收测试，不是真实机会”、不要行动，以及原文链接是占位地址。
即时邮件与 Digest 各一封，收发地址与冻结 SHA 在发送前核对；Digest 到真实 10:30 才冻结，
没有伪造未来处理时间。使用 QQ SMTP TLS 465、30 秒超时、单层无适配器重试，最多两次尝试。

10:33:19、10:33:20，两封分别取得真实最终 250，本地 accepted 与每封一次尝试一起保存，
退出后恢复暂停。10:35:28 再执行，attempted=0、accepted 新增=0，原尝试总数仍为 2。
Message-ID、冻结 MIME、具体收发地址和日志留在受限实例内，不复制私人数据到仓库。
**SMTP 接受不等于收件箱到达。** 本次用户随后明确确认“两封都收到”，因此工程即时邮件与 Digest
已有本地接受及人工实际收件两类证据；不据此声称生产校园提醒已启用或持续投递已验收。

## Linux 事务、备份与真实进程中断

- 初始化至 0007、重复初始化通过；真实 systemd 模板 verify/calendar 通过。
- 另一个进程持实例写锁时，写入命令明确 `writer_lock_busy` / 退出 1；退出后初始化重新获取锁成功。
- 隔离 `sleep` oneshot 的 2 秒 systemd 超时实际终止进程，Result=timeout、ExecMainStatus=15。
  这验证 Linux manager 的超时，不等于已覆盖采集/SMTP 每个网络窗口或断电。
- 生产库停写持锁，SQLite backup API 与 raw 复制得到 125 通知、10 版本、20 响应、16 原文，
  专项校验通过，无孤立文件。不是只复制 live SQLite 主文件。
- 工程邮件发送前保存 2 pending 快照，发送后保存 2 accepted / 2 attempts 快照；
  冻结 BLOB、成员、投递和尝试逐字段、逐字节一致，均通过 `verify_backup`。
- 从 pending 快照恢复到独立目录，**首次修改先暂停**，不注入 SMTP 凭据、不安装 timer。
  真实子进程经业务接口提交一封 sending 后写 ready，父进程发 SIGTERM，returncode=-15。
  重开数据库仍有 1 sending + 1 pending。
- 暂停下 drain 仅将遗留 sending 恢复一次为 uncertain，attempted=0；第二次恢复不后移 due，
  另一封仍 pending。accepted 恢复副本 attempted=0、两封 accepted 保留；恢复阶段 network_requests=0。
  sending / uncertain / accepted 三类副本专项校验全部通过。

这些是本机 WSL/Linux 上真实文件、SQLite、进程终止及真实 SMTP 接受证据；
未验证真实断电、介质损坏、SMTP 已接受但本地未提交的实际终止窗口、异地恢复或一周连续运行。

WSL_E_DISTRO_NOT_FOUND；同 SID / USERPROFILE / HKCU 的 PowerShell 诊断能枚举该发行版。
改为 PowerShell 参数调用后任务与实际 WSL sleep 进程保持运行，原失败原因未最终定位，
不能据此宣称是权限问题或发行版损坏。具体入口与宿主休眠/注销边界见 [WSL 指南](../wsl-deployment.md)。
