## 实现与边界

`runtime.full_lock_wait_seconds` 默认 180 秒，允许 0–600 秒，0 表示立即拒绝。仅 `scheduled-run --mode full` 使用它，邮件启用和关闭两条调用路径相同；普通采集、手动 crawl、独立邮件和其他写入命令仍立即拒绝争锁。

采集绝对时间预算在取得锁之前建立，等待、取得锁后的准备和 HTTP 都消耗原预算。只对 flock 的 EAGAIN/EACCES 有限等待，不重跑锁内业务、不增加 HTTP 重试层。超时区分 `writer_lock_timeout` 与原采集预算先耗尽的 `writer_lock_budget_exhausted`；取得锁前不打开业务数据库、建运行、归档或联网。`finally` 关闭描述符覆盖等待中断及业务异常。等待起止事件保留来源、run_id、阶段、等待毫秒和有限错误。

Windows 提供 [修复器](../../deploy/windows/repair-keepalive.ps1)和[保活运行脚本](../../deploy/windows/wsl-keepalive.ps1)。修复器校验拥有者与已知任务 action，先备份，再保留登录触发和主体、增加每五分钟无限重复、关闭两项电池限制，保留 IgnoreNew、无执行时限和原失败重启设置。维护应先禁用任务，避免周期恢复与人工停止互相竞争。

保活脚本追加 UTC 启动/退出、run_id、进程 ID 和有限退出码，不保留子进程任意输出；日志上限 1 MiB、两份轮转。强制终止可能没有退出行，不能据此推断根因。执行策略预检不计安装器自己的 Process 覆盖，本机实际 RemoteSigned，**没有更改或绕过执行策略**。修复器本身不隐式停止或启动任务，部署步骤见 [WSL 指南](../wsl-deployment.md)。
