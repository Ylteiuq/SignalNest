## 问题与修正

v1 只检查所选“截止”引句是否包含于 NoticeFacts.time_evidence，而该集合也包含开始时间、行政步骤和报名指令。只要整篇另有有效 deadline_at，这些片段就可能被误标为 rule_supported。

回归原样保留以下工程输入，使用既有 HTML 的内存副本并经过真实 Parser、归档、入库和只读查询；它是本轮构造的查询边界反例，不是新增校园原文或此前两个生产规则漏报案例：

```text
标题：本科生科研训练项目报名通知
正文：报名开始时间为2026年9月1日。报名截止时间为2026年9月28日23:59。
模型选择的截止原句：报名开始时间为2026年9月1日
```

旧实现对开始时间、区间起点、普通报名指令、学院提交声明和删掉学院主体的引句五项均误标为支持；正确的回归在修复前五项全部失败。修复后以上引句保持 unknown / deadline_quote_scope_unknown，正文提取出的实际截止仍单独保留，不能借它为错误引句背书。

查询协议升为 campus-query-v2。新增查询层 DeadlineEvidence，复用未修改的 v8 事实提取器，分别重放完整时间声明及模型原句；排除其他时间标题，二者均须支持原通知的同一截止上界及 lower boundary。同文出现在支持与行政语境时，缺少位置的引用保持未知。新增 facts.deadline_evidence 让模型看到少量完整支持声明，time_evidence 继续兼容。

最多检查前8项、返回4条、每条500字符、核对8处同文出现。无法独立确认、完整声明过长或移除“日前”导致精度改变均保持未知；不建设第二套日期 Parser，也不持久化内存探针。生产事实/规则 v8、Parser、正文摘要、schema、历史决策和冻结邮件没有改写。
